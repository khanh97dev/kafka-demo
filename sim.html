Kịch bản thử (và thuật ngữ nó chứng minh)

  1. Data skew / hot partition: chọn hot key → 1 partition lag vọt; thêm consumer không giúp vì 1 partition chỉ gán cho 1 consumer trong cùng group.
  2. Parallelism ≤ partition count: thêm consumer thứ 4 khi có 3 partition → consumer idle.
  3. At-least-once: auto commit + crash → record đã xử lý nhưng chưa commit bị redelivery → consumer phải idempotent.
  4. At-most-once: commit trước xử lý + crash → skipped tăng, không duplicate.
  5. Producer retry: acks=0 + timeout → mất record; acks=1/all, idempotence off + timeout → duplicate; bật idempotence thì broker dedup.
  6. Partition expansion: +1 partition → hash(key) % N đổi, mất ordering guarantee cho key cũ. Lên kế hoạch partition từ đầu.
  7. Rebalance (eager protocol): join/leave/crash → stop-the-world ~1.5s. Thực tế giảm bằng CooperativeStickyAssignor, static membership (group.instance.id).

Bảng thuật ngữ

Broker
Server Kafka lưu partition và phục vụ producer/consumer. Cluster thật thường ≥ 3 broker.
Topic
Kênh logic chứa record cùng loại (ở đây: orders).
Partition
Đơn vị song song & thứ tự: một commit log append-only. Thứ tự chỉ đảm bảo trong 1 partition.
Record / Message
Bản ghi gồm key, value, timestamp, headers.
Offset
Số thứ tự của record trong 1 partition (0,1,2…), bất biến.
LEO (Log End Offset)
Offset kế tiếp sẽ được ghi = "end" ở bảng partition.
Committed offset
Offset consumer group đã xác nhận xử lý, lưu ở topic nội bộ __consumer_offsets. Vạch trắng.
Consumer lag
LEO − committed offset. Chỉ số quan trọng nhất để giám sát consumer.
Partitioner
Chọn partition: có key → hash(key) % N; key null → sticky/round-robin.
Producer acks
0 / 1 / all — đánh đổi giữa latency và độ bền (durability). Kết hợp min.insync.replicas.
ISR (In-Sync Replicas)
Tập replica theo kịp leader. acks=all chờ toàn bộ ISR.
Idempotent producer
ProducerId + sequence number → broker loại record retry trùng (exactly-once cho 1 producer/partition).
Consumer group
Nhóm consumer chia nhau partition của topic; mỗi partition chỉ thuộc 1 consumer trong group. Nhiều group đọc độc lập.
Group coordinator / Rebalance
Broker điều phối membership; mỗi lần thành viên đổi thì phân chia lại partition (assignment).
Delivery semantics
at-most-once (commit trước), at-least-once (commit sau), exactly-once (transactions / idempotent sink).
Retention
Record không bị xoá khi consumer đọc; chỉ xoá theo thời gian/dung lượng (hoặc compaction). Vì vậy replay được bằng cách reset offset.
